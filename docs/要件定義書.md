## 1. システム概要

### 1.1 目的

本システムは、成人向け漫画サイト **WNACG（绅士漫画）** のユーザーアカウントに紐づく**お気に入り（収藏夹）**を自動的にクロールし、漫画をローカルへダウンロード・管理するためのセルフホスト型 Web アプリケーションである。ダウンロードした漫画は **CBZ 形式**（`ComicInfo.xml` メタデータ入り）にパッケージングされ、同梱の漫画リーダー **Komga** で閲覧できる。

NAS（特に Synology/群晖）上の Docker 環境での運用を主たる想定とする。

### 1.2 提供価値（ビジネス要件）

| # | 価値 | 概要 |
|---|------|------|
| BR-1 | お気に入り漫画の自動ダウンロード | WNACG アカウントのお気に入りから漫画情報を取得しローカルに保存 |
| BR-2 | CBZ 自動パッケージング | ダウンロード画像を `ComicInfo.xml` メタデータ付き CBZ に自動変換 |
| BR-3 | Komga リーダー統合 | ダウンロード先を Komga のライブラリと共有し、即座に閲覧可能 |
| BR-4 | NAS フレンドリーなデプロイ | Docker Compose による一括デプロイ（群晖向け構成あり） |
| BR-5 | 新作の自動検出 | お気に入り作者の新規作品を検索し「最近更新」として提示 |

### 1.3 利用者（アクター）

- **単一ユーザー（オーナー）**: 認証機構を持たない単一テナント前提。WNACG アカウント資格情報は環境変数で固定設定。
- **外部システム**: WNACG サイト（クロール対象）、発布ページ（最新ドメイン取得元）、Komga（閲覧）。

## 2. システム構成・アーキテクチャ

### 2.1 コンテナ構成（4 サービス）

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  frontend    │─────▶│   backend    │─────▶│   db         │
│ Next.js      │ HTTP │  FastAPI     │ SQL  │ PostgreSQL15 │
│ :13000→3000  │ SSE  │ :18000→8000  │      │ :15432→5432  │
└──────────────┘      └──────┬───────┘      └──────────────┘
                             │ Selenium/Chromium
                             ▼
                      ┌──────────────┐
                      │ WNACG サイト │（外部）
                      └──────────────┘

      ┌──────────────┐   downloads ディレクトリを共有（ボリューム）
      │   komga      │◀───────────────────────────┐
      │ :25601→25600 │                             │
      └──────────────┘                  backend のダウンロード先 = Komga のライブラリ
```

- **frontend**: Next.js（App Router）。ブラウザに UI を提供。バックエンド API を呼び出し、SSE で進捗を受信。
- **backend**: FastAPI。REST API + SSE。Selenium/Chromium でサイトをクロールし、画像をダウンロードして CBZ 化。
- **db**: PostgreSQL 15。漫画・最近更新・タスク・アプリ設定を永続化。
- **komga**: 漫画リーダー。`komga-data`（= backend の `downloads`）ボリュームを共有して同一ファイルを閲覧。

### 2.3 並行実行モデル

| 処理 | 実行制御方式 | 排他の単位 |
|------|------------|-----------|
| 収藏夹同期 (`sync`) | **シングルトン**（`SyncSingleton`） | プロセス内 1 実行のみ。二重要求は HTTP 409 |
| 最近更新同期 (`sync_recent_updates`) | **シングルトン**（`RecentUpdatesSingleton`） | プロセス内 1 実行のみ。二重要求は HTTP 409 |
| ダウンロード (`download`) | **キュー**（`DownloadQueueManager`、シングルトン実行器） | 要求は拒否されずキュー投入。1 件ずつ逐次実行 |

- 同期 2 種は互いに独立リソースのため**並行可能**。
- いずれも FastAPI の `BackgroundTasks` でバックグラウンド実行され、進捗は DB と SSE に反映。

## 4. 機能要件

機能の網羅的な一覧は [機能一覧表.md](./機能一覧表.md) を参照。本章では主要機能群の振る舞いを記述する。

### 4.1 収藏夹（お気に入り）同期 [FR-SYNC]

**目的**: WNACG アカウントのお気に入りに登録された全漫画情報を取得し、`mangas` テーブルへ保存する。

**処理フロー**（`SyncService.execute_sync_task`）:
1. シングルトン取得（既に実行中なら失敗扱い）。
2. **ローカルファイル整合性検証**（`verify_local_files`）を先行実行。DL 済みフラグが立つが CBZ が存在しない場合は状態をリセット。
3. `MangaCrawler` を初期化し、設定の資格情報で**ログイン**。
4. 書架ページ `users-users_fav.html` を開き、**作者別カテゴリリンク**（`users-users_fav-c-<id>.html`）を抽出。
5. カテゴリ（作者）ごとにページネーションを辿り、漫画リンク（`photos-index-aid-*`）を**ジェネレータでストリーム取得**（リアルタイム同期）。
6. 各漫画について:
   - `manga_url` で既存判定。既存ならページ数等を必要に応じ更新（`updated_count++`）。
   - 新規なら `mangas` に保存（`added_count++`）後、**詳細ページをクロール**して `page_count` / `updated_at` / `cover_image_url` を補完。
7. 進捗を逐次 `TaskManager.update_task` で更新（SSE 配信）。
8. 完了時に `added_count` / `updated_count` を結果に格納。

**特記事項**:
- カテゴリ名のうち除外語（`全部`/`管理分類`/`書架`/`书架`/`我的書架`）はカテゴリ抽出時にスキップ。
- ページ送りは「`.next > a`（後頁）」リンクのみを使用。最大 100 ページで打ち切り。
- 重複 URL 検出・訪問済み URL 検出でループ防止。

### 4.2 漫画ダウンロード [FR-DL]

**目的**: 漫画をサイトから取得し、`downloads/<作者>/<タイトル>.cbz` として CBZ 化。

**キュー方式**（`DownloadQueueManager` / `DownloadService`）:
- **単体**（`POST /api/download/{manga_id}`）/ **一括**（`POST /api/download/batch`）/ **最近更新から**（`POST /api/download-from-update/{update_id}`）いずれもキューに投入。
- 投入時の判定:
  - 漫画が存在しない → スキップ/404。
  - 既に `completed` かつ `is_downloaded` → スキップ（タスク作成しない）。
  - 既に `pending`/`running` のタスクあり → 既存タスクを返す（重複投入防止）。
  - それ以外 → `pending` タスクを新規作成。
- 実行器（`download_executor`）は**シングルトン**で 1 件ずつ逐次処理。キューが空になるまでループ、各件後に 0.5 秒スリープ。

**1 件のダウンロード処理**（`execute_download_task`）:
1. タスクを `running` に。
2. 既 DL 済みなら即 `completed`。
3. ログイン。失敗時はタスク `failed`。
4. `download_status = "downloading"` に更新。
5. 詳細クロール（`get_manga_details`）でメタデータ取得（`ComicInfo.xml` 用にも使用）。
6. **画像 URL 一覧クロール**（`get_manga_images`）。取得不能なら `failed`。
7. `download_manga_stream` で画像を**マルチスレッド並行ダウンロード**（既定 5 スレッド、`download_threads`）。
   - **ブレークポイント再開（断点续传）**: 既存かつサイズ > 0 のファイルはスキップ。
   - 先頭画像を封面（カバー）として `covers/` にコピー。
   - 進捗は DB（`downloaded_pages`）とタスク（進捗率 = DL 比率 × 90%）に反映。
8. 全画像取得後、**CBZ（ZIP_DEFLATED）を生成**し、`ComicInfo.xml` を同梱。
9. 一時ディレクトリ（`downloads/<作者>/<タイトル>/`）を削除。
10. `mangas` を更新（`is_downloaded`, `download_status=completed`, `downloaded_at`, `cbz_file_path`, `cover_image_path`, `file_size`, `downloaded_pages`）。タスクを `completed`（進捗 100%）。

**ファイル名サニタイズ**:
- タイトル: 英数字と ` -_` のみ残し、空白は `_` に置換。
- 作者: 英数字と ` -_（）()` のみ残し、空白は `_`。空なら `未知作者`。

### 4.3 最近更新（新作検出）同期 [FR-RU]

**目的**: お気に入り作者の新作を検索し、`recent_updates` テーブルに提示する。

**処理フロー**（`RecentUpdatesService.execute_sync_recent_updates_task`）:
1. シングルトン取得。
2. `mangas` から**作者の一意リスト**を取得し、設定の `excluded_categories` を除外。
3. 各作者について、お気に入り内の**最新 `updated_at`** を基準日 `since_date` とする（無ければ 2000-01-01）。
4. ログイン。
5. 各作者を**検索**（`search_author_updates`）。検索 URL は `/q/?q=<作者>&f=_all&s=create_time_DESC&syn=yes`。
   - 結果は作成日時降順。`since_date` より新しい作品のみ収集。
   - 古い作品に到達した時点で以降は更に古いため**打ち切り**（効率化）。
6. 取得作品を `recent_updates` に upsert（`manga_url` 一意）。
7. 当該作者の `since_date` より古い `recent_updates` レコードを削除。
8. 進捗・結果（`added_count` / `deleted_count`）を反映。

### 4.4 サイト側お気に入り登録 [FR-FAV]

**目的**: ローカルの漫画を WNACG サイト側のお気に入り（作者フォルダ）へ登録し、`is_favorited` を立てる。

**処理フロー**（`FavoriteService.add_to_favorite`、`POST /api/add-to-favorite`）:
1. 漫画 URL から `aid` を抽出（`photos-index-aid-(\d+).html`）。
2. ログイン。
3. 収藏フォーム `users-addfav-id-<aid>.html?ajax=true` を取得し、`select[name=favc_id]` のカテゴリ一覧を解析。
4. 作者名にマッチするカテゴリ ID を特定（完全一致 → 部分一致）。
5. Selenium の Cookie/UA を使って `users-save_fav-id-<aid>.html` へ `favc_id` を **POST**（requests 経由）。
6. HTTP 200 を成功とみなし、`mangas.is_favorited = True`。

> 注: 「最近更新」一覧でのみ未収藏漫画にハートボタンが表示される（収藏一覧では表示しない設計）。

### 4.5 ローカルファイル整合性・状態同期 [FR-FILE]

| 機能 | エンドポイント | 概要 |
|------|--------------|------|
| ファイル検証 | `POST /api/verify-files` | DL 済みフラグの漫画について CBZ の実在を検証。欠損時は状態リセット（再 DL 可能化）。 |
| 下载状态更新 | `POST /api/update-download-status` | `downloads/` 配下を走査し、ファイル名・作者フォルダで DB と突合。新規 DL 済み判定・欠損リセット。 |

突合は DB 側のタイトル/作者に DL 時と同じサニタイズを適用して行う。

### 4.6 タスク管理・リアルタイム進捗 [FR-TASK]

- 全長時間処理は `tasks` テーブルで状態管理（`pending`/`running`/`completed`/`failed`、進捗 0-100）。
- **SSE**（`GET /api/events`）で `task_created` / `task_updated` を全クライアントへブロードキャスト。30 秒無通信でハートビート（`: heartbeat`）。
- フロントは `EventSource` で購読。切断時は**フォールバックポーリング**（タスク詳細 10 秒 / 実行中一覧 30 秒）。
- **起動時クリーンアップ**: アプリ起動時に `pending`/`running` のタスクを全件 `failed` 化（Docker 再起動で中断したタスクの後始末）。手動清理は `POST /api/tasks/cleanup`。

### 4.7 漫画管理 [FR-MANGA]

- 一覧取得（`GET /api/mangas`）。
- 削除（`DELETE /api/manga/{id}`）: CBZ・カバー画像も物理削除。
- フロントでは作者別グルーピング表示の切替、カバープレビュー表示の切替、複数選択・一括削除、漫画カードからの外部リンク遷移（`manga_url`）を提供。

### 4.8 アプリ設定 [FR-CONFIG]

- `app_config`（シングルトン行 `id=singleton`）に**手動サイトドメイン**（`manual_manga_site_url`）を保持。
- 取得（`GET /api/settings`）/ 更新（`PUT /api/settings`）。URL は `http(s)://` で始まる必要あり。
- 設定があればドメイン自動取得（発布ページ解析）より**優先**して使用。
- フロントの設定ダイアログでは併せて「プレビュー表示」「作者別分類」の表示オプションも操作（これらはクライアント状態）。

## 5. 非機能要件

| 区分 | 要件 / 実装状況 |
|------|----------------|
| 認証・認可 | アプリ自体に認証なし（単一ユーザー前提）。WNACG 資格情報は環境変数で固定。 |
| CORS | バックエンドは**全オリジン許可**（`allow_origins=["*"]`、credentials 許可）。 |
| 可用性 | Docker `restart: unless-stopped`。DB は healthcheck 付き。起動時に中断タスクを自動 failed 化。 |
| 性能 | 画像ダウンロード並行（既定 5 スレッド）、原図 URL 取得並行（既定 3 スレッド）。ダウンロードは断点续传で再取得を最小化。 |
| データ永続化 | PostgreSQL（`postgres_data` ボリューム）。CBZ/カバー/ログはホストボリューム。 |
| ロギング | loguru による構造化ログ。コンソール（DEBUG, カラー）、詳細ログ（日次ローテーション）、エラーログ（90 日保持）、クローラログ（15 日保持）。`backend/logs/`。 |
| マイグレーション | Alembic を起動時に自動適用（JPA 風オートマイグレーション）。無効リビジョン検出・基準マイグレーション生成など自己修復ロジックあり。 |
| エラーハンドリング | 各層で例外捕捉しタスクを `failed` に。クロールは要素 stale 対策・リトライ的フォールバックを実装。 |
| スクレイピング配慮 | 各ページ取得後に `sleep`（2〜5 秒）。最大 100 ページ制限。 |

## 7. API 仕様

詳細は [API一覧.md](./API一覧.md)。全エンドポイントは `/api` プレフィックス（設定のみ `/api/settings`）。

| メソッド | パス | 概要 |
|---------|------|------|
| GET | `/` | ルート（疎通） |
| GET | `/health` | ヘルスチェック |
| GET | `/api/mangas` | 漫画一覧 |

## 8. 外部サイト連携（クローラ）仕様

### 8.1 ドメイン取得
- `manual_manga_site_url`（設定）があれば最優先。
- 無ければ**発布ページ**（`PUBLISH_PAGE_URL`、既定 `https://wn01.link`）を requests + BeautifulSoup で解析し、`ul > li > a[target=_blank]`（`i` タグを含む）を候補抽出。`wn01.link` / `google.cn` を除外し、疎通確認（HTTP 200）が取れた最初の URL を採用。

### 8.2 ログイン
- ヘッドレス Chromium で `users-login.html` を開き、`login_name` / `login_pass` を入力して送信。
- ログイン成否は遷移先 URL・ページ内文字列（`我的空間` 等）で判定。

### 8.3 クロール対象ページと抽出
| 用途 | URL パターン | 主な抽出物 |
|------|-------------|-----------|
| 書架 | `users-users_fav.html` | 作者カテゴリ `users-users_fav-c-<id>.html` |
| 一覧 | カテゴリ URL + `-page-N` | 漫画リンク `photos-index-aid-*`、頁数 `p.l_detla` |
| 詳細 | `photos-index-aid-<id>.html` | タイトル `h2`、頁数、更新日（`YYYY-MM-DD`）、封面 `img[src*=wnimg]`、分類、標籤、上传者、簡介 |
| 画像一覧 | 詳細ページ各ページ | 閲覧リンク `photos-view-id-*`（表示順を厳守） |
| 原図 | `photos-view-id-*.html` | `img[src*=wnimg]` かつ `/data/` を含み `/t/`（サムネ）を含まない URL |
| 検索 | `/q/?q=...&s=create_time_DESC` | `ul.col_2 > li.cate-*` の作品（日時・頁数・封面） |

- 原図取得は**ログイン不要**のため、専用の一時 driver を並行生成（既定 3 並行）して高速化。
- ページネーションは原則「後頁」リンク追跡、検索のみページ番号計算で次ページ特定。

### 8.4 ComicInfo.xml 生成
`utils/comic_info.py` が以下を出力（Komga 互換）:
- Title / Writer（作者）/ Series（タイトルから推測）/ PageCount
- Year・Month・Day（更新日から）/ Summary / Genre（分類から雑誌/同人/単行本へマッピング）/ Tags
- LanguageISO（既定 `zh-CN`）/ Web（漫画 URL）/ Manga=`YesAndRightToLeft`（右→左）
- Translator または Editor（タグに「翻訳」を含むかで上传者を訳者/編集に割当）

## 11. 既知の制約・課題

リバースエンジニアリング中に確認した、実装上の注意点・潜在的な不整合:

1. **`POST /api/add-to-favorite` のハンドラに型注釈欠落**（[routers/manga.py:44](../backend/app/routers/manga.py#L44)）。`def add_to_favorite(request, ...)` と Pydantic モデルが関数内定義のため、FastAPI が正しくボディを解析しない可能性が高い。実質クエリ/未バインドとなり 422 等を招くおそれ。
2. **README と実装の乖離**: README は `POST /api/add-to-collection` を記載するが、実装は `/api/add-to-favorite`。
3. **CORS 設定の二重定義**: compose の `CORS_ORIGINS` は使われず、コードは常に全許可（`*`）。
4. **収藏夹同期の進捗率計算が常に 90%**（`int(processed/max(processed,1)*90)`）— 総件数が事前不明のため進捗が実質的に固定値になる。
5. **SSE のイベントループ運用**: バックグラウンドスレッドからの `broadcast_sync` はイベントループ状態に依存し、環境によっては配信されないケースがありうる（フォールバックポーリングで救済）。
6. **単一ユーザー・無認証**: 公開ネットワークへ直接露出してはならない（資格情報・コンテンツ保護の観点）。
7. **`mangas` モデルの `updated_at` と `updated_at_db` の二重定義**（[models.py:20,35](../backend/app/models.py#L20)）— Python クラス属性として後者が前者を上書きする形になっており、要確認。
8. **スクレイピング依存**: 対象サイトの DOM 構造・ドメイン変更に脆い。CSS セレクタ（`paginator` / `l_detla` / `gallary_item` 等）に強く依存。
9. **法令・利用規約遵守**: 対象サイトの規約に従い、過度なアクセスを避ける運用が前提（README にも明記）。
