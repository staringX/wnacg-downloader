# 移行テスト戦略（ゴールデンマスター）

> [requests-bs4移行計画.md](./requests-bs4移行計画.md) の付属資料。
> Selenium → requests+BeautifulSoup 移行で**現状の動作を確実に保持**するためのテスト方式と運用手順。
> 整備日: 2026-06-30

## 1. 方針

移行で変更されるのは**クローラ層（HTML 解析）**のみ。よって解析を純関数に切り出し、
**保存した HTML フィクスチャ → 解析 → ゴールデン JSON 比較**で挙動を固定する（ゴールデンマスター方式）。

| Tier | 対象 | 方式 | 決定性 | 自動化 |
|------|------|------|:------:|:------:|
| **A（主）** | クローラ HTML 解析 | フィクスチャ→純パーサ→ゴールデン比較 | ◎ | pytest |
| B（副） | 読み取り専用 GET API | 起動中バックエンド応答のスナップショット比較 | ◎ | スクリプト |
| C | sync / download / favorite | ゴールデン化しない（非決定・副作用・非同期）。A で間接担保 + 手動 E2E スモーク | △ | チェックリスト |

> sync/download は実サイト依存で非決定的・DB 書込み/ファイル DL の副作用・task_id+SSE の非同期のため、
> HTTP レベルのゴールデン化は不適。これらは「クローラ解析(A)が同一なら同一に振る舞う」という前提で
> A により担保し、最後に手動 E2E で確認する。

## 2. 構成物

```
backend/
├── app/crawler/parsers.py          # 純解析関数（HTML→dict、副作用なし）= 移行の解析契約
├── scripts/capture_golden.py       # フィクスチャ+ゴールデン生成（要ログイン）
├── scripts/snapshot_api.py         # 読み取り API スナップショット（capture/compare）
└── tests/
    ├── fixtures/*.html             # 凍結した実 HTML（shelf/detail/view/search/addfav）
    ├── golden/*.json               # 期待解析結果（ドリフト検出基準）
    ├── api_snapshots/*.json        # 読み取り API ベースライン（Tier B、capture で生成）
    └── test_crawler_golden.py      # pytest（ゴールデン比較 + オラクル検証 + 純粋性）
```

`tests/test_crawler_golden.py` は 2 層で守る:
- **ゴールデン比較**: フィクスチャを `parsers` で解析し `golden/*.json` と完全一致を検証（移行でロジックを差し替えても出力が同じなら緑）。
- **オラクル検証**: 既知の真値をハードコード検証（例: 原図 URL は `/data/` を含み `/t/` を含まない、封面は絶対 URL）。ゴールデンが「緑だが内容は壊れている」状態を防ぐ。

## 3. 運用手順

### 移行前（ベースライン確定）— 実施済み 2026-06-30
```bash
cd backend
.venv/bin/python scripts/capture_golden.py          # Tier A: フィクスチャ+ゴールデン生成
.venv/bin/python -m pytest tests/test_crawler_golden.py -v   # 緑を確認（現状: 11 passed）
# （任意）バックエンド起動中に Tier B ベースライン
API_BASE=http://localhost:18000 .venv/bin/python scripts/snapshot_api.py capture
```

### 移行中（各フェーズ）
- `parsers.py` の実装を移行版に差し替え/拡張するたびに `pytest tests/` を実行。
- **ゴールデンは編集しない**（移行で出力が変わったら原則バグ。意図的変更時のみ capture で更新し差分をレビュー）。

### 移行後（再現性確認）
```bash
.venv/bin/python -m pytest tests/test_crawler_golden.py -v   # 全緑 = 解析挙動を保持
API_BASE=... .venv/bin/python scripts/snapshot_api.py compare # Tier B 差分ゼロ
```
さらに手動 E2E スモーク（Tier C）:

| # | 操作 | 期待 |
|---|------|------|
| 1 | `POST /api/sync` | task 完了、`mangas` 件数が従来同等 |
| 2 | 単体 `POST /api/download/{id}` | CBZ 生成・ページ数一致・封面保存 |
| 3 | `POST /api/sync-recent-updates` | `recent_updates` 取得 |
| 4 | `POST /api/add-to-favorite` | `is_favorited` 更新 |
| 5 | `POST /api/verify-files` | 整合性検証が従来同等 |

## 4. ゴールデンの妥当性（独立検証済み）

ゴールデンは `parsers.py` で生成しているため、それ単体では「決定性」しか保証しない。
**正しさは以下で独立に担保**している:
- フェーズ0 PoC で実サイトの値と一致を実測（[移行計画 フェーズ0結果欄](./requests-bs4移行計画.md)）。
- `parsers.py` のセレクタは現行クローラ（改版修正後）と一致。
- オラクル検証で主要フィールドの不変条件をハードコード。

現時点のゴールデン要点（base=`www.wn07.cfd`, aid 239091）:
- 詳細: title=「…これからの夜…」/ page_count=24 / cover=`https://t4.wnacgimg.date/data/t/2390/91/...` / tags=[沒有漢化, 無修正, さわたしゆん]
- 原図: `https://img5.wnimg1.ru/data/2390/91/231.png`（`/data/` 直下・非 `/t/`）
- 収藏一覧: 19 件 + next_url あり / カテゴリ 65 件

## 5. 注意事項

- **フィクスチャには対象サイトの HTML（成人向けタイトル等）が含まれる**。Git 管理の可否は利用者判断。
  リポジトリに含めない場合は `backend/tests/fixtures/` と `backend/tests/golden/`、`api_snapshots/` を
  `.gitignore` に追加し、`capture_golden.py` を各自実行する運用にする（ただし CI では再現できなくなる）。
- ゴールデンはサイト改版で陳腐化しうる。改版検知時は capture で再生成し、差分をレビューして更新する。
- 認証情報はプロジェクトルート `.env` 参照。スクリプトはレート制御（リクエスト間 1.2 秒）を実装。
- dev 依存は `requirements-dev.txt`（pytest）。venv へは `uv pip install --python .venv/bin/python pytest` 等で導入。
