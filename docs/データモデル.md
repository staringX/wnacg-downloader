# データモデル（テーブル定義）

> [要件定義書.md](./要件定義書.md) の付属資料。SQLAlchemy ORM（[backend/app/models.py](../backend/app/models.py)）に基づく。
> DBMS: PostgreSQL 15。マイグレーションは Alembic（起動時自動適用）。

---

## ER 概要

```
mangas (お気に入り漫画)          recent_updates (作者の新作)
  ├ id (PK, UUID)                 ├ id (PK, UUID)
  ├ manga_url (UNIQUE) ◀──┐       ├ manga_url (UNIQUE)
  └ author ───────────────┼─────▶ └ author
                          │         （author で論理的に関連。FK 制約はなし）
download-from-update で    │
recent_updates → mangas へ─┘

tasks (非同期タスク)              app_config (アプリ設定・単一行)
  ├ id (PK, UUID)                 └ id (PK = "singleton")
  ├ task_type                         manual_manga_site_url
  ├ status
  └ manga_id / manga_ids (論理参照)
```

※ テーブル間に物理的な外部キー制約は定義されていない（疎結合）。

## 1. `mangas` — お気に入り漫画

| カラム | 型 | 制約 / 既定 | 説明 |
|--------|-----|-----------|------|
| `id` | String | PK, UUID 自動 | 主キー |
| `title` | String | NOT NULL, index | タイトル |
| `author` | String | NOT NULL, index | 作者（カテゴリ名） |
| `manga_url` | String | NOT NULL, **UNIQUE** | 漫画ページ URL（自然キー） |
| `file_size` | BigInteger | nullable | CBZ サイズ（バイト） |
| `page_count` | Integer | nullable | 頁数 |
| `updated_at` | DateTime | nullable | サイト上の更新日 |
| `is_downloaded` | Boolean | 既定 False, index | ダウンロード済みフラグ |
| `downloaded_at` | DateTime | nullable | ダウンロード完了日時 |
| `cover_image_url` | String | nullable | 封面 URL |
| `cover_image_path` | String | nullable | 封面ローカルパス |
| `cbz_file_path` | String | nullable | CBZ ローカルパス |
| `download_status` | String | 既定 `not_started`, index | DL 状態（下記遷移参照） |
| `downloaded_pages` | Integer | 既定 0 | DL 済み頁数（断点续传用） |
| `is_favorited` | Boolean | 既定 False, index | サイト側お気に入り登録済みか |
| `created_at` | DateTime | server_default now | 作成日時 |
| `updated_at_db` | DateTime | server_default/onupdate now | DB 更新日時 |

> ⚠️ クラス定義上 `updated_at`（20 行目）と `updated_at_db`（35 行目）が存在。Python 属性として後者が前者を上書きする恐れあり（[要件定義書 §11-7](./要件定義書.md)）。

### `download_status` 状態遷移
```
not_started ──(DL 開始)──▶ downloading ──(成功)──▶ completed
     ▲                          │
     │                          └──(失敗)──▶ failed
     └──(ファイル欠損検出: verify/update-status でリセット)──
```

| `cover_image_url` | String | nullable | 封面 URL |

## 3. `tasks` — 非同期タスク状態

| カラム | 型 | 制約 / 既定 | 説明 |
|--------|-----|-----------|------|
| `id` | String | PK, UUID 自動 | 主キー |
| `task_type` | String | NOT NULL, index | `sync` / `download` / `sync_recent_updates` / `batch_download`* |
| `status` | String | NOT NULL, index | `pending` / `running` / `completed` / `failed` |
| `progress` | Integer | 既定 0 | 進捗率 0-100 |
| `total_items` | Integer | nullable | 総項目数 |
| `completed_items` | Integer | 既定 0 | 完了項目数 |
| `message` | String | nullable | 状態メッセージ |
| `error_message` | String | nullable | エラーメッセージ |
| `manga_id` | String | nullable, index | 関連漫画 ID（download 用） |
| `manga_ids` | String | nullable | JSON 形式 ID リスト（batch 用） |
| `result_data` | String | nullable | 結果データ（JSON 文字列） |
| `created_at` | DateTime | server_default now | 作成日時 |
| `updated_at` | DateTime | server_default/onupdate now | 更新日時 |
| `completed_at` | DateTime | nullable | 完了日時 |

> *`batch_download` はモデルのコメントに記載があるが、実際の一括 DL は個別 `download` タスクをキュー投入する実装。

## インデックス方針

検索・フィルタに使う以下に index を付与:
- `mangas`: `title`, `author`, `is_downloaded`, `download_status`, `is_favorited`
- `recent_updates`: `title`, `author`, `updated_at`, `is_downloaded`, `download_status`
- `tasks`: `task_type`, `status`, `manga_id`

## 一意制約

- `mangas.manga_url`, `recent_updates.manga_url` が自然キー（重複登録防止）。
- 並行同期時の UNIQUE 違反は `rollback` + 既存レコード再取得でハンドリング。
